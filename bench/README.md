# Benchmark protocol

For application write-route coverage, run `cargo build --release`, then `python bench/paired_unsafe_route_inventory.py --all-accepts --compare-error-bodies` and repeat with `--role member` and `--role anonymous`. The probe expands every non-Rails POST, PATCH, PUT, and DELETE route from the pinned Campfire route table, sends an invalid CSRF token to disposable instances, and compares status, response media type, redirect destination, and packaged error-body hash for HTML, JSON, Turbo Stream, and wildcard requests. It checks route recognition and rejection order, not valid writes or their side effects.

For paired visual snapshots, run `cargo build --release` and `python bench/paired_visual_pages.py --output-dir /tmp/rustfire-visual-review`, then `python bench/paired_visual_pages.py --width 390 --height 844 --max-difference 0.003 --output-dir /tmp/rustfire-visual-mobile`. The probe starts the pinned Campfire and Rustfire with matching disposable fixtures, signs into both in Chromium, captures fifteen room, boost, account, profile, search, member, bot, form, notification-setting, custom CSS, and push-subscription states, and saves their images and difference maps. The desktop gate allows under 0.2% differing pixels; the phone-sized gate allows under 0.3% because the sampled room includes generated product and URL text. These sampled viewports and account states do not establish visual parity across the full application.

For the signed-in no-room welcome state, add `--no-rooms` and use a separate output directory at either viewport. The fixture removes the administrator's room membership in both disposable databases before login, checks the empty message area appears, and compares the loaded sidebar and full screenshot. This checks one user with no room memberships, not every empty-account state.

For direct navigation to `/rooms` in that state, run `python bench/paired_empty_room_index.py` after the release build. It removes the administrator's memberships, checks twelve path and Accept combinations against pinned Campfire, and compares exact error-body hashes for HTML and JSON responses. It separately checks that `/` still serves the welcome page and anonymous room-index requests still redirect to sign-in. Campfire returns a packaged 500 from its room-index route when there is no last room; the probe preserves that observed behavior without treating it as a healthy flow.

For a full imported-history pagination check, run `cargo build --release` and `python bench/paired_large_import.py`. It seeds 16,230 distinct-time messages into a disposable pinned Campfire database, imports the stopped database, and compares all 406 message pages from both apps. Every page must match ordered message IDs, ETag, Last-Modified, and parsed HTML after generated-value normalization; the empty terminal page must return 204. Use `--messages N` for another history size (at least 41). Add `--read-clients 32 128 --read-seconds 5 --campfire-workers 22 --report bench/results/large-import-message-reads.json` to measure both full 200 and conditional 304 reads in both server orders after the parity check. This checks a seeded single-room history, not production migration or sustained load.

For a saved malformed ActionText message, run `cargo build --release` and `python bench/paired_import_malformed_action_text.py`. The probe creates the malformed message through pinned Campfire's HTTP route, stops Campfire, imports its database, and compares the missing search entry, exact trimmed message-list fragment, and edit-page 500 response with Rustfire. It checks that the importer reports the search row as preserved missing, not reindexed. This covers one failure state in a small account.

For a varied imported rich-text history, run `cargo build --release` and `python bench/paired_import_rich_corpus.py`. It posts 66 sanitizer, formatting, Unicode, entity, carriage-return, and malformed-HTML cases through pinned Campfire, stops the source, imports it, then compares every message ID, saved ActionText source, FTS row, and parsed individual presentation plus the complete parsed latest and older pages after generated-value normalization. Add `--full-sweep` to cover all 227 rich-filter cases and compare all six message pages. Add `--read-clients 32 128 --seconds 5 --campfire-workers 22 --report bench/results/imported-rich-corpus-reads.json` without `--full-sweep` to reproduce the recorded checked latest-page reads in both server orders. This is one disposable account without uploaded inline media or sustained writes.

For a multiroom imported history, run `cargo build --release` and `python bench/paired_large_graph_import.py --messages-per-room 4000`. The fixture has 16,000 distinct-time messages spread across one open room, two private rooms, and one direct room; the administrator can access three rooms, while a second member can access all four. The probe imports a stopped Campfire database and compares all 700 reachable message pages, including ordered IDs, exact ETag and Last-Modified values, and parsed HTML after generated-value normalization. Add `--read-clients 32 128 --read-seconds 5 --campfire-workers 22 --report bench/results/large-graph-import-reads.json` for both-order mixed latest-page reads across seven user-room targets. Each measured response must match its target's validator, status, media type, 40 message roots, and 320 CSRF fields. This measures short, read-only traffic on the same host as the load client. The target-file format accepted by `checked_get.go` supports per-target `expected_etag`, `expected_last_modified`, `expected_message_count`, `expected_csrf_count`, and optional `expected_sha256`.

The same multiroom probe compares four complete parsed search pages: broad 100-result searches for both users, an administrator search with no access to the member-only room, and a member search that finds that room's latest 100 messages. The fixture supplies matching source and imported VAPID keys through a push subscription. Add `--search-clients 32 128 --read-seconds 5 --campfire-workers 22 --search-report bench/results/large-graph-import-search-reads.json` for a separate, both-order search read sweep. Three nonempty user-query targets are measured; every response must have the expected message and CSRF-field counts and contain a marker from its newest expected message. The empty inaccessible-room search is compared for parity but not timed. `checked_get.go` also accepts per-target `expected_contains` strings.

For VAPID import states, run the multiroom probe with `--messages-per-room 61 --vapid-state absent`, then `configured`, then `subscribed`. The first run has no source key or subscriptions and verifies that the imported account stays keyless with matching parsed page heads; the second imports a configured key despite having no subscriptions; the third imports the key and a subscription. Each run also checks message pagination and search visibility. The default is `subscribed`.

For Hotwire Native navigation route parity, run `cargo build --release` and `python bench/paired_turbo_native_routes.py`. It compares 150 recede, resume, and refresh GET/HEAD responses against pinned Campfire on disposable signed-in and anonymous fixtures. For CSRF precedence, run `cargo build --release` and `python bench/paired_csrf_precedence.py --all-accepts --include-anonymous --compare-bodies --token-channels --multipart-token-fields`. It starts matched disposable databases and compares 144 signed-in and anonymous unsafe requests against pinned Campfire, including account method-override forms. It requires matching status, media type, redirect path, body length, and SHA-256 for HTML, JSON, Turbo Stream, and wildcard `Accept` headers. Nine URL-encoded form/header combinations check valid, invalid, missing, and duplicate tokens and the searches they save. Six multipart cases check the actual `authenticity_token` field, duplicate-field order, unrelated fields, message text, saved message IDs, and staged-file cleanup after rejection. It does not cover every route or malformed-body variant.

For routing order versus CSRF, run `python bench/paired_csrf_write_routes.py` after the release build. It compares 29 requests with absent, bad, or valid tokens, including unmatched and read-only write routes, bot-key method override, and a message post to a deleted room. Error responses are compared by status, media type, redirect, body length, and SHA-256; the successful deleted-room page is compared by its stable shell fields and normalized composer frame. It does not cover every write method or body type.

For signed mention presentation, run `cargo build --release` and `python bench/paired_mention.py`. It starts disposable Campfire and Rustfire fixtures with the same source secret, user names, bio, avatar timestamps, and room. It compares autocomplete SGIDs, parsed message presentation, and searchable plain text after posting bare and embedded-content ActionText attachments, a Trix figure, a duplicate mention, a mention of a nonmember, a signed mention after that member is banned, and User attachments with invalid current and Rails 7 signatures. Campfire's own `Message#mentionees` output is compared with Rustfire's saved recipient rows: the invalid-signature User attachments render and remain searchable but do not become notification recipients. This checks eight mention cases; other editor output and notification paths still need parity checks.

For bot mention webhooks, run `cargo build --release` and `python bench/paired_mention_webhook.py`. The probe adds two bots and local webhook URLs to disposable fixtures, starts Campfire's Resque worker with isolated Redis, and captures each app's outgoing JSON on a local receiver. It requires no shared-room delivery for plain `@bot` text, one equal payload each for signed, duplicate, and Trix-figure attachments, delivery to a bot in a direct room without a mention, and delivery to a peer when a bot posts a signed mention through the API. A bot's own direct-room message produces no webhook to itself. A rendered invalid-signature bot mention produces no webhook. It compares the bot API's full message-list JSON in all three rooms, including rich ActionText mention wrappers, after normalizing timestamps and URL origins. Add `--sample-dir /tmp/mention-json-samples` to retain both normalized JSON files. Unavailable endpoints and sustained delivery remain separate work.

For webhook replies, run `cargo build --release` and `python bench/paired_webhook_replies.py`. The probe uses disposable databases, isolated Redis, one Campfire Resque worker, and a local reply server. It posts ten signed bot mentions in sequence and compares outgoing payloads, saved reply IDs and attachment metadata, original attachment bytes, and the complete normalized bot message-list JSON. The cases are 200 plain text, 200 HTML, a text response streamed over eight seconds, stalled text and partially received ZIP responses that trigger the seven-second timeout reply, empty 200 plain text, a 500 plain-text attachment, a 200 PNG attachment, a 26 MiB ZIP attachment, and a 500 response without Content-Type that creates no reply. The probe also checks that Rustfire removes the partially received ZIP temporary file. This checks ten local response shapes; it does not measure webhook throughput, retries, redirects, or other MIME types.

For a paired load that also saves bot replies, run `python bench/paired_webhook_reply_capacity.py --posts 120 --rate 24 --delay-ms 25 --campfire-workers 16 --resources --report bench/results/webhook-replies-16-rust-first.json`, then repeat with `--campfire-first` and a distinct report path. Socket setup precedes the measured interval. The probe does not cover push delivery, attachments, other browser channels, long-run stability, or maximum capacity.

For webhook timeout, connection failure, and manual retry behavior, run `cargo build --release` and `python bench/paired_webhook_failures.py`. It uses disposable databases, isolated Redis, one Resque worker, and a local receiver that waits beyond both apps' seven-second timeout. The probe requires identical timeout payloads, a matching timeout bot reply and normalized bot message list, then points the bot at a refused local port. Neither app creates a bot reply for that second message; Campfire retains one failed Resque job and Rustfire retains one failed SQLite job. It requeues the failed job through Resque and Rustfire's `webhook-jobs retry` command, respectively, then compares the delivered JSON and retained failure records with `retried_at` set. It does not compare every failure metadata field or other network errors.

For Rustfire's webhook queue, run `cargo build --release` and `python tests/webhook_queue.py`. This seeds 80 bots in a direct room, posts one message to a local receiver that deliberately holds requests open, and requires all 80 deliveries and an empty queue afterward. It then restarts Rustfire with one pending and one expired claimed job, requires both deliveries, and checks that both jobs are removed. One bot is deactivated before restart; its queued webhook still sends and saves a text reply. The probe establishes burst retention and restart recovery for this fixture; it does not compare maximum webhook throughput or all failure semantics with Campfire's Resque worker.

For a matched webhook burst comparison, run `python bench/paired_webhook_burst.py --bots 80 --campfire-workers 8` and `--bots 320 --campfire-workers 8`, repeating each with `--campfire-first`. The trial measures a short burst on one host, not sustained throughput, retries, or a maximum user count.

For a 30-second paired webhook load, run `python bench/paired_webhook_sustained.py --bots 8 --posts 360 --rate 12 --campfire-workers 22 --timeout 180`, then repeat with `--campfire-first`. For paired presence behavior, run `cargo build --release` and `python bench/paired_presence.py`. The probe starts both servers on disposable SQLite fixtures, with isolated Redis for Campfire, and checks that each clears a fresh three-connection membership on server startup. It then uses one authenticated Action Cable socket per app. It subscribes to the read channel, sets an unread marker, opens the room over HTTP, and checks that neither the marker nor read-channel traffic changes. It subscribes to two distinct presence identifiers for the same room, checks both read events and saved connection counts, sends an unconfirmed identifier message, refreshes with a new unread marker set, and unsubscribes in sequence. A second socket sequence seeds a stale three-connection record before subscribe, refresh, and unsubscribe; both apps must reset its count to one, one, and zero while preserving the unread marker on refresh and unsubscribe. A third sequence calls `present` twice on one subscribed identifier, then alternates explicit `absent` and `refresh` actions. It checks every connection-count transition, the extra read event, and whether present clears an unread marker while refresh preserves it. Saved `updated_at` transitions are compared for startup reset and explicit actions: `present` leaves it alone, while `absent` and `refresh` touch it.
